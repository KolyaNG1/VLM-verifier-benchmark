# Разметка научных иллюстраций

Задача отдельная от бенчмарка верификатора: сгенерировать подробные английские
описания к каждой картинке набора, чтобы по ним потом работал SigLIP. Описание
должно быть буквальным — каждая стрелка с направлением и концами, каждая подпись
дословно, — потому что проверять его будет модель, которая ничего не домысливает.

Инструмент написал Николай. Здесь он выложен как есть плюс этот документ.

Пример того, что модель выдала на фигуре `golden/juri_orig/document_101/figure_2`:

> 1. On the left side of the diagram, a vertical flow begins with a black flask
> icon labeled "Microalgae culture solution" at the top. A downward red arrow

Это тот уровень детализации, который требуется: направление каждой стрелки, её
начало и конец, подписи блоков в кавычках, нумерованные пункты.

## Что надо решить до полного прогона

Три вещи выяснились при проверке, и каждая требует ответа команды.

**1. Формат вывода: `.txt` или `.json`.** Инструмент кладёт одобренное описание
рядом с картинкой как `figure_N.txt` (`annotation_tool/files.py`, функция
`annotation_path`). Промпт, который обсуждался в чате, требует `figure_N.json`
с единственным полем `description`. Расхождение надо снять до прогона, иначе
придётся переделывать все файлы.

**2. Few-shot примеров сейчас один, а нужно пять.** В
`prompts/annotation_fewshot.md` подключён единственный эталон — DKU-схема из
`examples/`. Задание требует пять размеченных вручную. Один пример работает, но
именно на пяти держится консистентность формата между картинками.

Добавляются правкой yaml-блока в начале промпта:

```yaml
few_shot_examples:
  - image: nikolay_ai_360_annotation/examples/dku_reference.png
    annotation: nikolay_ai_360_annotation/examples/dku_reference.txt
  - image: <путь к вашей картинке>
    annotation: <путь к вашему описанию>
```

**3. Модель по умолчанию дорогая.** В CLI прописан `openai/gpt-5.6-sol`.

## Быстрый старт

Набор PNG кладётся рядом с папкой инструмента:

```
рабочая папка/
  nikolay_ai_360_annotation/     <- этот код
  nikolay_ai_360_student/        <- ваши картинки
```

Ключ OpenRouter — в `.env` рядом с `run.py`, скопировать из `.env.example`.
В репозиторий он не попадает.

```powershell
python nikolay_ai_360_annotation/run.py validate
python nikolay_ai_360_annotation/run.py run --model z-ai/glm-4.6v --limit 5 --workers 2 --max-pending-review 4
```

Команды выполняются из **родительской** папки, не из папки инструмента.

Что происходит дальше: инструмент генерирует пачку кандидатов, кладёт их рядом с
картинками как `figure_N.vlm_attempt_001.md`, открывает браузер и **ждёт вашего
одобрения**. Одобренное описание ложится рядом как `figure_N.txt`. Прогон можно
прервать и продолжить — очередь хранится в `review_state.json` в соседней папке
`nikolay_ai_360_annotation_artifacts`.

Флаг `--max-pending-review` не даёт нагенерить больше, чем вы успеваете
проверять глазами. Структура папок и имена картинок не меняются.

## Ключ у команды общий

Один и тот же ключ OpenRouter используют несколько человек, и прогоны каждого
уменьшают общий баланс. За время проверки остаток просел заметнее, чем стоили
собственные вызовы.

Проверить остаток:

```powershell
python -c "import re,httpx;from pathlib import Path;k=re.search(r'OPENROUTER_API_KEY\s*=\s*(\S+)',Path('.env').read_text(encoding='utf-8')).group(1);d=httpx.get('https://openrouter.ai/api/v1/credits',headers={'Authorization':'Bearer '+k},timeout=60).json()['data'];print('осталось: $%.2f'%(d['total_credits']-d['total_usage']))"
```

Если нужен отдельный лимит на ключ, он выставляется в настройках OpenRouter.
