# Разметка научных иллюстраций для SigLIP

> Ветка `vlm-image-annotation`. Задача отдельная от бенчмарка VLM-судьи, который
> живёт в ветках `main` и [`zhenya`](../../tree/zhenya).

Нужно сгенерировать подробное английское описание к каждой картинке набора.
Описание потом проверяет SigLIP — верификатор, сопоставляющий текст с
изображением. Он **ничего не домысливает**, поэтому описание должно быть
буквальным: каждая стрелка с началом, концом и направлением, каждая подпись
дословно, каждая панель на своём месте.

Формулировка заказчика: «представьте, что вы объясняете самому тупому человеку,
что значит эта картинка».

### Пять эталонов размечены вручную

Лежат в `examples/`, пути повторяют структуру исходного архива. К каждому `.png`
рядом лежит `.txt` с описанием — ровно тот формат, который инструмент ожидает.

| Эталон | Тип фигуры | Чему учит модель |
|---|---|---|
| `examples/golden/ml_orig/document_185/figure_1` | пайплайн | три типа линий: сплошная, пунктир, штрих; подписи на стрелках; цвет как смысл |
| `examples/golden/ml_orig/document_86/figure_1` | блок-схема с ромбом | ветвление на три пути с условиями, схождение стрелок, терминальный узел |
| `examples/golden/ml_orig/document_58/figure_6` | сетка два на четыре | сначала раскладка, потом ячейки; заголовки рядов и столбцов; подписанные области внутри картинки |
| `examples/golden/ml_orig/document_171/figure_6` | двухпанельный график | оси с диапазонами, легенда, цвета кривых; **честное описание обрезанной панели** |
| `examples/golden/ml_orig/document_191/figure_1` | текстовая панель | фигуры без единой стрелки, вложенная нумерация, формулы |
| `examples/dku_reference` | пайплайн с фото | исходный эталон Николая |

Пятёрка подобрана по типам намеренно. Если бы все примеры были блок-схемами,
модель поплыла бы на графиках и сетках — это самая частая ошибка при few-shot.

Уровень детализации, из `document_185/figure_1.txt`:

> A solid black right-pointing arrow leaves the right side of the "Memory M"
> cylinder and points to the "Ret(M, q, k)" rectangle. The small black label
> "top-k" is written above this arrow.

Не «блоки соединены стрелкой», а откуда, куда, какого типа линия и что на ней
написано.

Отдельно про `document_171/figure_6`: у этой картинки левая панель обрезана краем
изображения. В описании это сказано прямо — что заголовок читается частично, что
вертикальной оси не видно, что подпись обрезана. Модель на таком примере учится
не выдумывать недостающее.

## Что осталось: доработка промпта

Сам текст промпта — всё, что в `prompts/annotation_fewshot.md` идёт после
yaml-шапки. Сейчас там инструкция Николая и один встроенный образец стиля.

Что стоит поправить, по убыванию важности.

**Убрать дублирование образца.** Раздел «Example of the required level of detail»
пересказывает DKU-эталон текстом, а тот же эталон уже подаётся картинкой через
few-shot. Модель получает его дважды, в двух разных формах. Либо убрать
текстовый образец, либо убрать DKU из yaml.

**Определиться с форматом вывода.** Инструмент кладёт описание рядом с картинкой
как `figure_N.txt` — см. `annotation_tool/files.py`, функция `annotation_path`. В
обсуждении задачи фигурировал другой формат: `figure_N.json` с единственным полем
`description`. **Это надо согласовать до полного прогона**, иначе придётся
переделывать все 159 файлов.

**Убрать разрешение на Markdown.** Последний абзац промпта разрешает заголовки,
жирный шрифт, ссылки и подчёркивание. Для SigLIP разметка — мусор: он сравнивает
текст с картинкой, а звёздочки и решётки к картинке отношения не имеют. Стоит
требовать чистый текст нумерованными пунктами.

**Зафиксировать длину.** Сейчас требований к длине нет. В размеченных эталонах
получилось 10–12 пунктов и 390–560 слов на картинку. Разумно записать эту вилку
в промпт, чтобы модель не сваливалась в три предложения на сложной схеме.

**Запретить служебные вступления.** Модель иногда начинает с «This figure
shows…» или «In this image we can see…». Для верификатора это пустые токены.

## Как запускать прогон

### Раскладка папок

Инструмент и набор картинок лежат рядом, команды выполняются из **родительской**
папки:

```
рабочая папка/
  nikolay_ai_360_annotation/     <- содержимое этой ветки
  nikolay_ai_360_student/        <- ваши картинки
```

Ключ OpenRouter — в `.env` рядом с `run.py`, скопировать из `.env.example`.
В репозиторий ключ не попадает.

### Пачками по пять

```powershell
python nikolay_ai_360_annotation/run.py run --model openai/gpt-5.6-sol --limit 5 --workers 2 --max-pending-review 4
```

Инструмент генерирует пять описаний, кладёт их рядом с картинками как
`figure_N.vlm_attempt_001.md`, открывает браузер и **ждёт вашего одобрения**.
Одобренное описание ложится рядом как `figure_N.txt`.

Флаг `--max-pending-review` не даёт нагенерить больше, чем вы успеваете
проверять глазами. Прогон можно прервать и продолжить: очередь хранится в
`review_state.json` в соседней папке `nikolay_ai_360_annotation_artifacts`.

Следующие пачки идут через `--offset`:

```powershell
python nikolay_ai_360_annotation/run.py run --model openai/gpt-5.6-sol --limit 5 --offset 5 --workers 2
python nikolay_ai_360_annotation/run.py run --model openai/gpt-5.6-sol --limit 5 --offset 10 --workers 2
```

### Почему именно пятёрками

Так требует третий пункт задания — отсматривать качество после каждой генерации.
Пять описаний проверить глазами реально, пятьдесят уже нет.

Крупнее брать не стоит и по другой причине: чем больше картинок уходит в один
запрос, тем сильнее модель теряет нить, и детали с одной картинки переползают на
другую. Для SigLIP нужна полнота по каждой картинке отдельно.

### Проверка перед первой пачкой

```powershell
python nikolay_ai_360_annotation/run.py validate
python nikolay_ai_360_annotation/run.py run --dry-run --limit 3 --no-browser
```

`--dry-run` создаёт файлы-кандидаты без единого сетевого запроса — удобно
убедиться, что пути и структура папок в порядке, ничего не потратив.

## Ключ у команды общий

Один и тот же ключ OpenRouter используют несколько человек, и прогоны каждого
уменьшают общий баланс. Остаток виден на <https://openrouter.ai/credits>. Если
нужен отдельный лимит на ключ, он выставляется там же в настройках.

## Требования заказчика

Из постановки задачи, чтобы не потерялось:

1. Разметить пять фотографий вручную, чётко фиксируя правила переходов стрелок и
   расположение картинок. — **сделано**, см. `examples/`
2. Скормить few-shot в VLM и просить по следующим фото такие же чёткие описания.
   — подключено, промпт требует доработки
3. После каждой генерации отсматривать качество по картинке. — обеспечивается
   режимом `--limit 5` с ручным одобрением в браузере
4. **Нейминги и структуры файлов внутри папок не менять.** — инструмент кладёт
   описание рядом с картинкой и папок не трогает, проверено на 159 файлах

Описания пишутся на английском, картинки при этом могут содержать текст на любом
языке — видимые подписи цитируются как есть.
