# Архитектура фреймворка экспериментов VLM

[← К глобальным знаниям](index.md)

## Состояние реализации

Первая версия реализована в пакетах [src/vlm_bench](../../src/vlm_bench) и
[viewer](../../viewer). В неё входят загрузчик 243 пар, подстановка маркеров
промпта, клиент OpenRouter, запись артефактов, последовательный исполнитель,
команды пакетного запуска и локальный HTML-просмотрщик. Базовый промпт находится
в [prompts/vlm_judge/v001_baseline.md](../../prompts/vlm_judge/v001_baseline.md),
а пошаговый запуск — в [README.md](../../README.md).

Реализованы и выполнены 12 автономных тестов, включая тесты загрузчика,
подстановки промпта, расчёта оценок, записи артефактов, имитации OpenRouter и
локального просмотрщика. 2026-08-20 по явному разрешению пользователя ручной
тест успешно выполнил один реальный запуск `document_1/figure_2`: два вызова
`orig → fail` модели `z-ai/glm-4.6v` вернули валидный JSON; стоимость составила
`0.00625178 USD`. Артефакты находятся в
`runs/20260820T105145Z__z-ai_glm-4.6v__v001_baseline__97d3bd7b`.

## Назначение первой версии

Первая версия запускает слепой диагностический бенчмарк на 243 искажённых
рисунках ML-поднабора. Каждая пара порождает два независимых сетевых вызова:
сначала исходный рисунок, затем изменённый. Модель, параметры, подпись,
текстовый блок и версия промпта одинаковы; в одном вызове присутствует только
одна картинка.

Проверенный `gold` не передаётся модели. После получения двух ответов фреймворк
добавляет эталонную метку и вычисляет парный исход по каждой оси.

## Принципы простоты

- Один пакет Python без тяжёлого фреймворка и без базы данных.
- Стандартные JSON/JSONL и обычные каталоги являются долговременным форматом.
- `requests` отвечает только за сеть; предметные расчёты не зависят от
  OpenRouter.
- HTML-просмотрщик состоит из отдельного HTML, CSS и JavaScript и работает
  через небольшой локальный сервер на стандартной библиотеке Python.
- Запуск всегда последовательный: исходный рисунок оценивается перед изменённым.

части, после чего не должен быть точкой входа фреймворка.

## Контракт набора данных

Объект `DatasetPair` содержит:

- `pair_id`: канонический ключ вида `document_1/figure_2`;
- `orig_pic`, `fail_pic`: абсолютные проверенные пути;
- `caption`, `text_block`, `text_block_source`;
- `sample_id`, `pdf_id`, `arxiv_id`, `figure_id`;
- `gold_is_corrupted`, `gold_lies`, `gold_objects` — только для последующей
  оценки, не для рендера промпта.

Загрузчик по умолчанию выбирает только строки `gold.is_corrupted == true`, для
которых существуют обе картинки и исходная строка. Ожидаемый размер — ровно
243 пары; любое другое число считается ошибкой целостности снимка данных.

Поддерживаемый выбор:

- `--limit N` и `--offset N` для первых 1, 10 или другого числа пар;
- повторяемый `--id document_N/figure_M`;
- `--ids-file path.txt` с одним идентификатором на строку;
- `--image-path PATH`, принимающий путь исходной или изменённой картинки;
- `--shuffle --seed 42` для воспроизводимой случайной выборки;
- явный `--include-clean` для будущего анализа 1 402 неизменённых примеров.

Выбор по идентификаторам сохраняет порядок пользователя. Повторы устраняются,
неизвестный либо неоднозначный ключ завершает запуск до сетевых расходов.

## Контракт промпта

Версия промпта — отдельный Markdown-файл. В нём разрешены маркеры `<caption>`,
`<text>` и `<image>` в любом порядке и любое число раз. Рендерер проходит файл
слева направо:

- `<caption>` превращается в текст подписи;
- `<text>` превращается в текстовый блок;
- `<image>` превращается в отдельную часть `image_url` с локальным PNG в
  base64;
- остальные фрагменты становятся текстовыми частями.

Поскольку OpenRouter допускает мультимодальные части только в пользовательской
роли, весь Markdown является версионируемым составным пользовательским
сообщением. Небольшое неизменяемое системное сообщение задаёт роль судьи и
требование вернуть только JSON. Маркер `<image>` обязан встретиться ровно один
раз в базовом промпте: повтор изображений технически поддерживается, но
валидатор предупреждает об этом как о дорогой и обычно ошибочной конфигурации.

Версия фиксируется тройкой: относительный путь файла, имя файла и SHA-256
исходных байтов. В каталог запуска копируется исходный Markdown, поэтому
редактирование рабочего файла не меняет прошлый опыт.

## JSON-ответ и проверка

Ответ VLM должен содержать:

- версию схемы;
- не менее трёх текстовых сущностей с цитатами;
- визуальные сущности и наблюдаемые признаки;
- сопоставления со статусами `supported`, `unsupported`, `missing`;
- счётчики `P`, `U`, `M` и `coverage`;
- оценки `faithfulness`, `clarity`, `compactness`, `style` из множества
  `{1, 3, 5}`;
- вычисленный моделью `overall`;
- краткий аудит каждой оси и предупреждения.

Фреймворк локально проверяет JSON, пересчитывает счётчики по сущностям,
`Coverage`, `F` и `Overall`. Авторитетными для метрик являются локально
пересчитанные значения. Ответ с неверным JSON, менее чем тремя текстовыми
сущностями или недопустимой оценкой получает одну автоматическую попытку
исправления новым независимым запросом; оба ответа и причина повтора
сохраняются. После повторной ошибки вызов помечается `invalid_response`, но
пакет продолжает работу.

## OpenRouter и начальные значения

| Параметр | Значение по умолчанию |
|---|---|
| Модель | `z-ai/glm-4.6v` |
| Адрес | `https://openrouter.ai/api/v1/chat/completions` |
| Температура | `0` |
| `top_p` | `1` |
| `seed` | `42` |
| Максимум выходных токенов | `4096` |
| Рассуждение | `medium`, с запросом доступных полей рассуждения |
| Формат | `response_format: {type: json_object}` + локальная схема |
| Потоковая выдача | выключена |
| Тайм-аут | 180 секунд |
| Сетевые повторы | 3 попытки с паузами 1, 3 и 9 секунд |
| Одновременные работники | 1, не настраивается в первой версии |
| Мягкий предел стоимости запуска | 5 USD, изменяемый параметром |
| Пороги F | `mid=0.60`, `max=0.80`, границы включены |
| Веса | `0.45/0.25/0.15/0.15` |

Перед запуском сохраняется снимок поддерживаемых моделью параметров, если
OpenRouter его вернул. Неподдержанный параметр не должен молча менять протокол:
он фиксируется как предупреждение или останавливает запуск, если влияет на JSON.
Секретный ключ никогда не записывается.

## Независимость вызовов

Для `orig` и `fail` создаются два отдельных HTTP-запроса без общей истории.
Порядок запуска фиксирован: `orig`, затем `fail`. Ошибка одного вызова не
подменяется результатом другого. Парный результат формируется только после
завершения обеих сторон и имеет состояния `complete`, `partial`, `failed`.

Кэширование в данном проекте означает локальное повторное использование уже
сохранённого успешного результата с тем же полным ключом: хэши картинки,
промпта и входного текста, модель и все параметры. Сетевой кэш поставщика не
считается гарантией воспроизводимости.

## Каталог одного запуска

```text
runs/20260820T153012Z__glm-4.6v__v001_baseline__a1b2c3d4/
├── run.json
├── prompt/
│   └── v001_baseline.md
├── samples.jsonl
└── samples/
    └── document_1__figure_2/
        ├── pair.json
        ├── orig/
        │   ├── request.json
        │   ├── response.raw.json
        │   └── result.json
        └── fail/
            ├── request.json
            ├── response.raw.json
            └── result.json
```

`run.json` содержит идентификатор, состояние, времена, выбранные пары,
конфигурацию, модель, версии Python и фреймворка, хэши манифестов и промпта,
сводные токены/стоимость/ошибки. Base64 картинки в артефакт не копируется:
`request.json` хранит безопасное представление сообщения, относительный путь,
тип, размер и SHA-256 файла. `response.raw.json` хранит полный ответ сервиса.
`result.json` содержит нормализованный ответ, локальные пересчёты и ошибки.
`samples.jsonl` — плоский индекс для быстрого просмотра и последующей аналитики.

Файлы записываются атомарно. `run.json` обновляется после каждого вызова;
прерванный запуск можно продолжить командой `resume`, не повторяя успешные
вызовы. Новая команда `run` всегда создаёт новый каталог.

## Команды, которые должна предоставить реализация

```text
python -m vlm_bench run --limit 1
python -m vlm_bench run --limit 10
python -m vlm_bench run --id document_1/figure_2 --id document_5/figure_3
python -m vlm_bench run --ids-file batch.txt
python -m vlm_bench run --image-path data/data/verifier_v0/figures/ml_l2_fail/document_1/figure_2.png
python -m vlm_bench resume runs/<run_id>
python -m vlm_bench validate-dataset
python -m vlm_bench render-prompt --id document_1/figure_2
python -m vlm_bench viewer --port 8080
```

Для первого реального прогона подготовлен ровно один явный ручной тест:

```text
python tests/manual_openrouter_one_pair.py --live
```

Без флага `--live` скрипт завершится до сети. С флагом он запустит одну пару
`document_1/figure_2`, то есть два вызова в порядке `orig → fail`, с пределом
стоимости 1 USD.

`render-prompt` и режим `--dry-run` обязаны работать без сетевого ключа и
показывать безопасный запрос без base64. Это основной способ проверить шаблон
до расходов.

## HTML-просмотрщик

Локальный сервер предоставляет только чтение каталога `runs/` и файлов набора.
Просмотрщик должен иметь:

- выбор запуска и отображение его состояния, модели, промпта, стоимости,
  токенов, длительности и числа ошибок;
- фильтры по `pair_id`, состоянию, `gold`, победе/ничьей/поражению и оценкам;
- список пар с краткими баллами `orig` и `fail`;
- детальную карточку с двумя картинками рядом, caption, text, `gold` после
  оценки, сущностями, аудитом и локально пересчитанными метриками;
- отдельные вкладки «разобранный результат», «сырой ответ», «запрос»,
  «промпт» и «метаданные»;
- явное отображение отсутствующего рассуждения как «не предоставлено»;
- отсутствие операций изменения и удаления артефактов.

HTML не сканирует файловую систему сам: `viewer_server.py` выдаёт JSON-список
запусков и безопасно обслуживает только разрешённые файлы внутри корня проекта.
Так картинки работают в браузере без копирования и без проблем `file://`.

## Проверки перед первым платным запуском

1. Загрузчик находит ровно 243 пары по умолчанию и отклоняет отсутствующие
   файлы/дубликаты.
2. Тесты подтверждают все границы правила F, веса и исходы пары.
3. Рендерер корректно обрабатывает повторяющиеся маркеры, Unicode и маркеры на
   границах файла.
4. Поддельные ответы OpenRouter проверяют успех, сетевую ошибку, неверный JSON,
   повтор и возобновление.
5. Режим `--dry-run --limit 1` создаёт полный каталог без сетевого вызова.
6. Просмотрщик открывает этот каталог и не выходит за разрешённые директории.
7. Затем пользователь вручную выполняет один реальный вызов пары, а после
   проверки результата — пакет из 10.

## Открытая граница первой версии

Режим сравнения Human / Our Pipeline / Frontier с передачей
эталона и кандидата документирован в дизайне оценки, но не входит в первую
реализацию `orig/fail`. Его добавление потребует отдельного типа входа и
отдельного имени протокола, чтобы результаты нельзя было случайно смешать.
