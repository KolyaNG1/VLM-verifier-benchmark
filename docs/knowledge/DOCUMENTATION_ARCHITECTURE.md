# Архитектура системы документации

[← К глобальным знаниям](index.md)

## Кратко

Документация разделена на первичные материалы, поддерживаемую связанную базу
знаний и правила её обслуживания. История работы хранится в задачах, актуальные
многократно полезные сведения — в тематических страницах, а центральные сводки
собираются автоматически.

## Подтверждённые сведения

- **Подтверждено:** входом в дерево ссылок является
  [`docs/index.md`](../index.md).
- **Подтверждено:** каждая глобальная цель или самостоятельное исследование
  получает задачу с описанием, журналом и выводами.
- **Подтверждено:** исследование обязано обновить и выводы задачи, и глобальную
  тематическую страницу, если знание полезно повторно.
- **Подтверждено:** дашборд, текущее состояние и оглавления разделов собираются
  `scripts/docs_ctl.py` из служебных полей основных страниц.
- **Подтверждено:** выдача номера и сборка защищены файловой блокировкой.
- **Подтверждено:** чистая первоначальная основа экспортируется командой
  `python scripts/docs_ctl.py export-template <каталог>` без предметных задач.
- **Устарело:** готовый чистый каркас ранее был создан в `project_start/`;
  при проверке 2026-08-20 этого каталога в рабочей области уже нет. Команда
  `export-template` остаётся подтверждённым способом повторно создать такой
  каркас; первая создаваемая задача получает номер `TASK_001`.
- **Подтверждено:** подробные правила находятся в
  [регламенте](../DOCUMENTATION_SYSTEM.md).

## Практические последствия

- Новый чат сначала читает индекс и состояние, затем создаёт или продолжает
  задачу.
- Будущий агент не должен повторно разбирать структуру или данные, если уже есть
  актуальная глобальная страница с доказательствами.
- Изменение поведения проекта и изменение документации происходят в одном
  содержательном этапе.
