# Структура набора verifier_v0

[← К глобальным знаниям](index.md)

## Кратко

`verifier_v0` содержит пары научных иллюстраций для проверки соответствия
рисунка тексту. Основной для проекта ML-поднабор — 1 645 рисунков из 208
статей: у каждого есть изменённая либо неизменённая версия `ml_l2_fail` и
связанная исходная версия `ml_orig`.

## Состав и расположение

Рабочий корень набора: `data/data/verifier_v0/`. В поле `image_path` записан
путь, начинающийся с `data/verifier_v0/`; его надо разрешать относительно
каталога проекта `data/`, а не относительно корня репозитория.

| Материал | Назначение | Проверенный объём |
|---|---|---:|
| `manifest_ml_l2_fail.jsonl` | Главный построчный манифест проверяемых рисунков и эталонной разметки | 1 645 рисунков, 208 статей |
| `figures/ml_l2_fail/` | Проверяемые изображения: часть специально искажена | 1 645 PNG |
| `manifest_ml_orig.jsonl` | Исходные записи и пути к эталонным изображениям | 1 667 рисунков |
| `figures/ml_orig/` | Исходные изображения статей | 1 667 PNG |
| `hints_ml_l2_fail.json` | Метаданные статей и список внесённых исправлений для анализа | 214 статей, 276 записей `fixed` |

`ml_l2_fail` содержит 243 искажённых и 1 402 неизменённых рисунка. Все 1 645
его рисунков имеют исходную пару; ещё 22 исходных рисунка не вошли в
`ml_l2_fail`.

## Схема строки главного манифеста

Каждая JSON-строка содержит следующие обязательные поля.

| Поле | Тип | Назначение |
|---|---|---|
| `sample_id`, `split` | строка | Уникальный идентификатор с префиксом разбиения и имя разбиения |
| `pdf_id`, `pdf_path`, `arxiv_id`, `title` | строка | Идентификаторы и метаданные статьи |
| `figure_id`, `figure_num`, `page` | строка, строка, целое | Идентификатор и страница рисунка в PDF |
| `caption`, `text_block` | строка | Подпись и связанный контекст статьи |
| `text_block_source` | строка | Происхождение текста: `mentions`, `same_page_context` или их сочетание |
| `image_path` | строка | Путь к PNG, разрешаемый относительно `data/` |
| `bbox_caption`, `bbox_image` | список из 4 вещественных чисел | Координаты подписи и рисунка в PDF |
| `gold` | объект | Эталонная разметка искажения |

`gold` всегда содержит булевы `is_corrupted` и `from_summary_fixed`, а также
списки строк `lies` (описания ошибок) и `objects` (затронутые объекты).
В ML-манифесте оба булевых признака совпадают. Описания `lies` свободны по
форме и не образуют надёжную нормализированную классификацию.

## Как собрать корректную пару

1. Прочитать строку из `manifest_ml_l2_fail.jsonl`; из неё взять `caption`,
   `text_block`, `gold` и путь к проверяемой картинке.
2. Нормализовать `sample_id`, удалив префикс `ml_l2_fail/`. Например,
   `ml_l2_fail/document_1/figure_1` становится `document_1/figure_1`.
3. Найти в `manifest_ml_orig.jsonl` строку с тем же относительным
   идентификатором после удаления `ml_orig/`; взять её `image_path` как путь
   к эталонной картинке.
4. Проверять одну картинку по тексту вслепую; исходное изображение применять
   только там, где протокол действительно требует парного сравнения.

Не следует соединять строки по полному `sample_id`: в нём различается префикс
разбиения. Не следует также подменять контекст строкой `ml_orig`: в 388 общих
парах отличаются хотя бы одно текстовое, координатное или разметочное поле.

## Вспомогательная разметка и качество

`hints_ml_l2_fail.json` содержит дату, идентификатор arXiv, название, авторов,
ссылки, сведения о страницах/таблицах/рисунках, имя файла и список `fixed`.
Элемент `fixed` имеет поля `name`, `object`, `lie`.

Эта разметка полезна для анализа внесённых изменений, но не заменяет `gold`:
208 из 214 статей подсказок есть в ML-манифесте, шесть — отсутствуют; 276
записей `fixed` не равны 243 искажённым строкам. При строгой оценке метка и
описание ошибки берутся только из `gold` строки `ml_l2_fail`.

## Соседние материалы вне границ ML-поднабора

В каталоге присутствуют `manifest_juri_*`, `manifest_bt_l2_fail.jsonl`,
смешанный `manifest_eval.jsonl`, общий `manifest.jsonl`, `summary.json` и
`unmatched_fixed.jsonl`. Общий манифест объединяет 5 818 строк пяти разбиений;
оценочный манифест из 735 строк смешивает ML, Juri и BT. Эти файлы не нужно
неявно загружать вместе с ML-поднабором.

## Практические последствия

- Загрузчик ML-поднабора должен принимать каталог `data/` как базу путей и
  явно выбирать `manifest_ml_l2_fail.jsonl`.
- Целевая метка обнаружения ошибки — `gold.is_corrupted`; текст ошибки для
  разбора — `gold.lies`.
- Для парного режима требуются два пути изображения и нормализованный ключ,
  а для одиночной оценки — текст, подпись, одно изображение и `gold` только
  на этапе подсчёта качества.
- Разделение на обучение, проверку и тест пока не определено этой страницей;
  особенно не следует автоматически считать `manifest_eval.jsonl` тестовой
  выборкой только ML-поднабора.
