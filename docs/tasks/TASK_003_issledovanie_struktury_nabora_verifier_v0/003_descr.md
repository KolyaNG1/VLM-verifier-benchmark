# TASK_003 — Исследование структуры набора verifier_v0

[← К дашборду](../../TASKS_DASHBOARD.md)

## Навигация

- [Журнал](./003_logs.md)
- [Выводы](./003_concl.md)

## Цель

Проверить на локальных файлах и задокументировать состав, схему записей,
связи между исходными и изменёнными рисунками, разметку и ограничения
ML-поднабора `verifier_v0`. Результат должен быть достаточен для начала
разработки фреймворка работы с данными.

## Границы

### Входит

- Исследование файлов `data/data/verifier_v0/manifest_ml_l2_fail.jsonl`,
  `manifest_ml_orig.jsonl`, `hints_ml_l2_fail.json` и деревьев рисунков.
- Проверка количеств, полей, путей, пар рисунков и качества разметки.
- Краткая фиксация назначения остальных манифестов, находящихся рядом.
- Создание глобальной страницы знаний и карточки первичного источника.

### Не входит

- Реализация загрузчика, разбиений для обучения или метрик.
- Повторная генерация набора и исправление исходных данных.
- Содержательный разбор каждого отдельного искажения.

## Требования пользователя

- 2026-08-20 — изучить и задокументировать структуру и устройство данных
  `verifier_v0` перед началом реализации фреймворка набора данных.
- 2026-08-20 — для строгой оценки считать поле `gold` построчного манифеста
  источником истины; `hints_ml_l2_fail.json` использовать как вспомогательную
  разметку для анализа и отладки.
- 2026-08-20 — разрешать `image_path` относительно каталога `data/`, а не
  корня проекта.

Добавляйте сюда каждое существенное уточнение пользователя с датой.

## План

1. Изучить существующие сведения о верификаторе и область исследования.
2. Прочитать схемы и посчитать статистики локальных файлов.
3. Проверить соответствие пар, путей и разметки.
4. Зафиксировать результат в задаче, глобальном знании и карточке источника.

## Допущения и ограничения

- Исследование относится прежде всего к ML-поднабору: `ml_l2_fail` и
  `ml_orig`. Другие разбиения описаны только для безопасной навигации.
- Равенство байтов исходного и неизменённого файла не является критерием
  разметки; контролируемым источником истины служит `gold.is_corrupted`.

## Рассмотренные варианты и обоснования

- **Решение:** строить пару по нормализованному идентификатору
  `document_N/figure_M`, а не по полному `sample_id`. Полные идентификаторы
  включают разные префиксы разбиений (`ml_l2_fail` и `ml_orig`) и поэтому не
  равны.
- **Решение:** использовать текст, подпись и `gold` из строки
  `manifest_ml_l2_fail`; соответствующая строка `manifest_ml_orig` нужна для
  пути к эталонной картинке. У 388 общих рисунков между манифестами различается
  хотя бы одно поле метаданных.
