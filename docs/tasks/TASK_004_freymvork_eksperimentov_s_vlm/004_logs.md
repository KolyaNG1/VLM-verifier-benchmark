## L-20260820-11 — Разобран неуспешный запуск document_13/figure_1

**Событие:** пользователь выполнил запуск одной пары по пути
`document_13/figure_1.png`; получено состояние `failed`. Новые запросы не
выполнялись, прочитаны только артефакты запуска.

**Результат:** оба вызова вернули HTTP 200 с первой сетевой попытки, но
завершились с причиной `length`: модель израсходовала все 4 096 выходных
токенов. В трёх из четырёх модельных попыток текст JSON отсутствует, в одной
попытке оригинала JSON обрывается на 408 символах. В каждой попытке на
рассуждение пришлось 3 968–4 095 токенов. Исполнитель сделал по две попытки
на сторону, потому что формат ответа не прошёл локальную проверку.

**Наблюдение:** фактическая стоимость четырёх ответов — `0.01656547 USD`, хотя
`run.json` показывает 0. Это дефект учёта: стоимость `invalid_response`
сохраняется без вложенного поля `usage`, которое читает сумматор. Второй дефект
состояния: `run.json` получает `complete` после окончания цикла даже когда
единственная пара имеет `failed`. Оба дефекта требуют отдельного исправления;
по просьбе пользователя код в этом разборе не менялся.

**Событие:** по требованию пользователя увеличен предел вывода, добавлены
человекочитаемые названия запусков и исправлены выявленные ошибки учёта.

**Результат:** значение `max_tokens` по умолчанию увеличено с 4 096 до 16 384.
Команда `run` принимает `--name`; имя сохраняется в `run.json`, участвует в
названии каталога и показывается в списке и сводке HTML-просмотрщика. Для
старых запусков сохранён показ технического идентификатора. Стоимость теперь
суммирует все модельные попытки, а итоговое состояние запуска отражает
неудачные и частичные пары. Денежный предел по умолчанию снят и задаётся только
явным `--max-cost-usd`; ручной тест одной пары сохраняет свой явный предел
1 USD. Все 13 автономных тестов прошли; реальных вызовов на этом этапе не было.

**Подтверждённая независимость:** исполнитель создаёт сначала один HTTP-запрос
только с `orig`, затем новый HTTP-запрос только с `fail`. Между ними не
передаётся история сообщений или ответ модели; повторно используемое соединение
не является общим контекстом модели.

## L-20260820-13 — Стороны пары переведены на параллельный запуск

**Событие:** пользователь запросил параллельно выполнять `orig` и `fail` одной
пары, сохраняя независимость и различимость сторон.

**Результат:** протокол переименован в `blind_orig_fail_parallel_v1`. Для пары
создаются две задачи в пуле из двух потоков; каждая получает новую HTTP-сессию,
свой список сообщений с одной картинкой и пишет только в свою папку `orig/` или
`fail/`. Пары пакета пока запускаются последовательно. Тест с синхронизационным
барьером подтвердил, что обе стороны действительно входят в клиент
одновременно, а `result.json` сохраняется раздельно.

**Методическое основание:** независимость определяется отсутствием общей истории
в сообщениях, а не порядком запросов. Отдельные `pair_id`, `side`, путь и
SHA-256 каждой картинки остаются в артефактах. Стоимость не меняется, ожидаемое
время одной пары становится близко к длительности более медленной стороны.
