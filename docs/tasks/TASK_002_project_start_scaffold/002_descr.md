# TASK_002 — Создание чистого каркаса project_start

[← К дашборду](../../TASKS_DASHBOARD.md)

## Навигация

- [Журнал](./002_logs.md)
- [Выводы](./002_concl.md)

## Цель

Создать в корне папку `project_start/`, которую можно сразу копировать как основу
любого нового проекта. Каркас должен содержать универсальные инструкции,
структуру документации, шаблоны и автоматизацию, но не историю текущего проекта.

## Границы

### Входит

- Универсальный `AGENTS.md`.
- Пустая, связанная и автоматически проверяемая структура `docs/`.
- Шаблоны задач, знаний, решений и источников.
- Служебная программа `scripts/docs_ctl.py`.
- Пустые дашборд, текущее состояние, задачи, знания, решения и источники.
- Автономная проверка каркаса и создание пробной первой задачи на временной копии.

### Не входит

- Код, данные и зависимости конкретного проекта.
- Задачи, журналы, выводы и предметные знания текущего репозитория.
- Архив старого проектного контекста.

## Требования пользователя

- 2026-08-20 — исходный запрос: Создание чистого каркаса project_start.
- 2026-08-20 — скопировать все системные файлы и структуру документации, пригодные
  для немедленного старта любого проекта.
- 2026-08-20 — очистить описания и журналы, если они относятся к прежним задачам.

## Критерии завершения

- [x] Папка `project_start/` создана.
- [x] В каркасе нет предметных задач, знаний и журналов текущего проекта.
- [x] Первая создаваемая задача получает номер `TASK_001`.
- [x] Проверка внутри каркаса завершается без ошибок.
- [x] Выводы и журнал этой задачи обновлены.

## План

1. Сделать экспорт по умолчанию полностью чистым.
2. Экспортировать основу в `project_start/`.
3. Проверить состав файлов и отсутствие проектных сведений.
4. На временной копии создать первую задачу и повторно проверить систему.
5. Обновить документацию текущего проекта.

## Допущения и ограничения

- Папка `project_start/` должна быть самодостаточной и не ссылаться на файлы за
  своими пределами.

## Рассмотренные варианты и обоснования

- Выбран чистый экспорт без `TASK_000`: системная история полезна разработчику
  каркаса, но становится шумом в каждом новом проекте.
- История разработки каркаса остаётся в текущем репозитории и никогда не входит
  в `project_start/`.
