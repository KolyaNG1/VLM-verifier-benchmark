# Обязательные правила работы с проектом

Этот файл содержит только универсальные правила работы агента. Сведения о
конкретном проекте хранятся в `docs/` и не должны дублироваться здесь.

## Документация — постоянная память проекта

Документация является общей памятью всех чатов и должна оставаться актуальной
после каждого содержательного этапа работы. История чата не является источником
истины: значимые требования, исследования, решения, результаты и проблемы должны
быть перенесены в документацию.

Перед любой содержательной работой:

1. Полностью прочитай `docs/DOCUMENTATION_SYSTEM.md`.
2. Начни навигацию с `docs/index.md`.
3. Прочитай `docs/CURRENT_STATE.md` и `docs/TASKS_DASHBOARD.md`.
4. Через ссылки найди текущую задачу, связанные задачи, глобальные страницы
   знаний и решения. Не читай всю документацию без необходимости.
5. Если обязательных файлов нет, сначала восстанови систему документации по
   шаблонам из `docs/templates/`.

## Задачи

Задача — самостоятельная глобальная цель с собственным результатом и критериями
завершения. Первый содержательный запрос в новом чате считается новой задачей,
если пользователь явно не продолжает существующую. Мелкое исправление или
уточнение внутри текущей цели новой задачей не является.

Исследование также всегда является задачей, даже если агент не меняет код или
данные. К исследованиям относятся, например:

- изучение структуры незнакомого проекта;
- разбор архитектуры и потоков данных;
- исследование датасета, форматов и качества данных;
- анализ библиотеки, внешнего интерфейса или научного метода;
- диагностика причины ошибки;
- сравнение подходов и проверка осуществимости.

Нельзя повторно исследовать проект только потому, что выводы остались в старом
чате. Перед исследованием ищи существующие выводы в глобальных страницах знаний
и связанных задачах. Если знания устарели, создай новую задачу или явно продолжи
существующую и обнови страницы.

Создавай задачу командой:

```text
python scripts/docs_ctl.py create "Название задачи"
```

Каждая задача хранится в `docs/tasks/TASK_<NNN>_<short_name>/` и содержит:

- `<NNN>_descr.md` — цель, границы, требования, критерии завершения,
  уточнения пользователя, план, варианты и краткие обоснования;
- `<NNN>_logs.md` — хронология только значимых событий;
- `<NNN>_concl.md` — актуальные выводы, результаты, проверки, проблемы,
  решения проблем и открытые вопросы.

`*_descr.md` является главной страницей задачи и связывает все её материалы.
Сохраняй краткие проверяемые обоснования и рассмотренные варианты, но не скрытое
пошаговое рассуждение модели.

## Обязательное документирование исследований

Если в ходе задачи агент узнаёт что-либо многократно полезное о проекте, он
обязан сделать две записи:

1. Подробно зафиксировать вывод и доказательства в `*_concl.md` задачи.
2. Создать или обновить тематическую глобальную страницу в `docs/knowledge/`.

Глобальная страница должна описывать актуальное знание, а не историю его
получения: структуру проекта, архитектуру, датасеты, интерфейсы, процессы запуска,
ограничения или другие устойчивые сведения. Она обязана ссылаться на задачи и
доказательства, из которых получен вывод. `docs/CURRENT_STATE.md` должен ссылаться
на такие страницы, а не копировать их целиком.

Все полезные наблюдения агента должны попасть хотя бы в выводы задачи. Не
заполняй глобальные страницы догадками: явно различай подтверждённый факт,
гипотезу, предложение, принятое решение и устаревшее утверждение.

## Обновление во время работы

- Новое существенное уточнение пользователя сразу заноси в `*_descr.md`.
- После важного действия, решения, эксперимента или препятствия добавляй запись
  в `*_logs.md`. Не копируй туда весь терминальный вывод.
- После появления или изменения вывода обновляй `*_concl.md` в том же сеансе.
- Если вывод полезен за пределами одной задачи, одновременно обновляй
  `docs/knowledge/` или `docs/decisions/`.
- Важное решение, влияющее на несколько задач, оформляй отдельной записью в
  `docs/decisions/`.
- Не сохраняй в документации пароли, ключи, токены и другие секреты.

После каждого содержательного изменения документации выполняй:

```text
python scripts/docs_ctl.py sync
```

Перед завершением этапа или ответом о выполненной работе выполняй:

```text
python scripts/docs_ctl.py check
```

Для создания чистой основы нового проекта из уже работающего проекта используй:

```text
python scripts/docs_ctl.py export-template <новый_каталог>
```

По умолчанию команда переносит только универсальные правила, пустую структуру,
шаблоны и служебную программу. Задачи, журналы, выводы и знания текущего проекта
не копируются; первая задача нового проекта получает номер `TASK_001`.

Если проверка нашла проблему, исправь её. Не объявляй задачу завершённой при
неактуальной или несвязанной документации.

## Параллельные чаты

- Один чат является единственным редактором своей активной папки задачи.
- Не изменяй папку другой активной задачи без необходимости. Связь или
  противоречие фиксируй в своей задаче и в служебных полях связанных страниц.
- Файлы задач и глобальные страницы знаний являются источниками истины.
  `TASKS_DASHBOARD.md`, `CURRENT_STATE.md` и страницы-оглавления являются
  автоматически собираемыми представлениями.
- Для выдачи номера задачи и сборки общих страниц используй `docs_ctl.py`: он
  применяет файловую блокировку и не позволяет двум чатам выдать один номер.
- Перед редактированием общего файла перечитай его с диска и сохраняй изменения
  других чатов. Не перезаписывай вручную автоматически собираемые блоки.
- Субагенты не являются общей памятью проекта. Если пользователь явно разрешил
  их использовать, основной агент назначает непересекающиеся области файлов и
  единолично обновляет общую документацию.

## Связность и актуальность

- Используй относительные Markdown-ссылки для файлов внутри проекта.
- Каждая страница должна быть достижима из `docs/index.md` по цепочке ссылок,
  иметь ссылку назад на страницу своего раздела и ссылки на связанные материалы.
- Не дублируй одно знание в нескольких местах. Храни подробность в тематической
  странице, а в сводках — краткое состояние и ссылку.
- При изменении кода, данных или решения найди затронутые страницы и обнови их в
  том же сеансе. Если проверить актуальность невозможно, явно пометь это как
  проблему и создай задачу на проверку.
- Старое утверждение не удаляй бесследно, если оно влияло на решения: пометь его
  устаревшим и укажи заменивший вывод или решение.

## Завершение задачи

Задача завершена только когда:

1. Выполнены её критерии завершения.
2. Результаты проверены соразмерно риску.
3. Обновлены описание, журнал и выводы задачи.
4. Исследовательские знания перенесены в `docs/knowledge/`.
5. Общие решения перенесены в `docs/decisions/`.
6. Описаны проблемы, способы их решения и открытые вопросы.
7. Выполнена команда `python scripts/docs_ctl.py check` без ошибок.

В итоговом ответе кратко перечисли изменённые материалы документации.
